## 一、应用概述

UIN Tool 是一个轻量级的插件化框架，允许你在 Android 上动态加载和运行第三方插件。支持**原生插件**（Java/Kotlin）和 **Web 插件**（HTML/CSS/JS），内置 Linux 终端、后端运行时和权限管理。

### 1.1 核心功能

| 功能模块 | 说明 |
|----------|------|
| 插件系统 | 原生（Java/Kotlin）和 Web（HTML/CSS/JS）插件 |
| 数据持久化 | 每个插件独立的 data/ 目录，更新时自动保留用户数据 |
| 终端环境 | 内置基于 PRoot 的完整 Linux 终端 |
| 后端集成 | 统一启动命令模式，内置 Debian 容器 / 实体 Termux 全局可选 |
| 容器运行时 | Proot 共享 Debian 容器，后端与宿主机环境隔离 |
| 插件仓库 | 从 GitHub 源浏览、搜索和安装插件 |
| 开发工具 | 创建向导、代码编辑器（Sora Editor）、模板导出 |
| 权限管理 | 应用权限和插件独立权限管理，状态持久化 |
| 备份恢复 | 备份/恢复插件和配置 |
| UI 个性化 | 38+ 颜色项、渐变背景、新拟态风格、玻璃效果 |
| 多语言支持 | 应用内多语言切换（中文/英文） |
| 桌面小部件 | 列表小部件（3x3）和 1x1 快捷方式 |
| 外部内容 | 系统分享/用其他应用打开的中转处理（openWith） |
| 插件多开 | 同一插件同时运行多个独立实例 |

### 1.2 插件类型对比

| 特性 | 原生插件 | Web 插件 |
|------|----------|----------|
| 开发语言 | Kotlin/Java | HTML/CSS/JS |
| 性能 | 最优 | 良好 |
| 热更新 | 需重新编译 | 无需编译 |
| 开发门槛 | 较高 | 较低 |
| 系统 API 访问 | 完全访问 | 通过 JS 接口（170+ API） |
| 数据存储 | PluginContext API | UINPlugin 存储 API |
| 后端支持 | 无 | 统一启动命令模式 |

## 二、首次启动

### 2.1 启动流程

用户点击图标 → 权限检查 → SplashActivity (启动页) → 检查首次启动

```
├── 是 → OnboardingActivity (引导页) → MainActivity
└── 否 → MainActivity
```

### 2.2 权限请求

首次启动时，应用会请求存储权限：

1. 显示权限说明对话框
2. 点击「去授权」跳转到系统设置
3. 授予权限后自动返回应用
4. 如果拒绝权限，应用会退出

### 2.3 引导页

首次安装或版本更新时，会自动显示引导页：

| 页面 | 内容 |
|------|------|
| 第1页 | 欢迎语 / 版本更新说明 |
| 第2页 | 插件管理功能介绍 |
| 第3页 | 插件开发工具介绍 |
| 第4页 | Web 插件支持介绍 |
| 第5页 | 准备就绪，开始体验 |

操作方式：
- 点击「下一步」翻页
- 点击「跳过」直接进入主界面
- 最后一页点击「开始体验」

## 六、自动更新

### 6.1 启动自动检测

每次启动应用时，系统会自动检查 GitHub 最新版本。

### 6.2 强制更新机制

当 Release Tag 格式为 {版本代码}-{版本名称}-1 时，会强制用户更新：

| Tag 格式 | 示例 | 强制更新 |
|---|---|---|
| x-y-z 且 z=1 | 2-1.0.1-1 | ✅ 是 |
| x-y-z 且 z=0 | 2-1.0.1-0 | ❌ 否 |
| x-y | 2-1.0.1 | ❌ 否 |

强制更新特点：

· 弹窗中「暂不更新」按钮被隐藏
· 用户必须选择「自动下载」或「手动下载」

### 6.3 更新选项

| 选项 | 说明 |
|---|---|
| 自动下载 | 在应用内下载 APK，完成后直接安装 |
| 手动下载 | 打开浏览器跳转到 GitHub Releases 页面 |
| 暂不更新 | 关闭对话框（普通更新可用） |
| 忽略此版本 | 记录忽略的版本，下次不再提示 |

## 十、插件管理

### 10.1 插件格式说明

插件文件扩展名为 .tpk，本质上是 ZIP 压缩包。

原生插件结构：

```
plugin.tpk
├── plugin.json      # 插件配置文件
├── icon.png         # 插件图标 (建议 128x128)
├── plugin.dex       # 编译后的 DEX 文件
├── src/             # 源码目录
└── res/             # 资源文件目录
```

Web 插件结构：

```
plugin.tpk
├── plugin.json      # 插件配置文件
├── icon.png         # 插件图标
├── web/             # Web 资源目录
│   ├── index.html   # 入口页面 (必须)
│   ├── style.css    # 样式文件 (可选)
│   └── script.js    # JavaScript 文件 (可选)
├── data/            # ✅ 插件数据目录（运行时创建）
└── cache/           # ✅ 插件缓存目录（运行时创建）
```

### 10.2 plugin.json 配置说明

```json
{
    "pluginId": "com.example.myplugin",
    "version": 1,
    "versionName": "1.0.0",
    "minHostVersion": 1,
    "name": "我的插件",
```

带后端的插件（WebView + 后端、CUI）需要启动一个后台服务（HTTP 服务等）。宿主如何启动它、用什么运行环境，由「管理」页的「**后端运行设置**」**全局统一配置**，对所有后端插件生效。

#### 12.5.1 后端实现：内置 Debian 容器还是实体 Termux

| 选项 | 说明 | 适合场景 |
|------|------|----------|
| **内置 Debian 容器**（默认） | 使用应用内置的 Debian 容器，通过 PRoot 运行后端，**无需安装任何东西** | 开箱即用，想省事 |
| **实体 Termux** | 调用设备上安装的 Termux（`com.termux`）运行后端，可用原生 Termux 生态 | 需要 pip/npm/apk 等完整软件包生态 |

- **内置 Debian 容器**：Debian rootfs 随应用内置（assets 离线恢复，约 19MB，首次一次性解压），不依赖网络安装
- **实体 Termux**：需设备已安装 Termux 并完成一次初始化，否则启动失败时会自动弹出引导

#### 12.5.2 后端环境（仅实体 Termux 可选）

| 选项 | 说明 |
|------|------|
| **Termux 本机** | 直接在 Termux 原生环境运行 |
| **Proot 容器** | 在 Proot 容器内运行（容器名可配置，默认 `debian`，如 `ubuntu` 需先安装） |

- 选 Proot 容器需填写容器名
- 内置 Debian 容器**强制**使用 PRoot 运行，此项不适用

#### 12.5.3 空闲自动回收

后端空闲超过设定时长自动停止，避免长期占用资源；插件活动请求会刷新计时。退出插件满设定时长后，其后端即被自动清理。时长可选预设 3 / 5 / 10 / 15 分钟（默认 5 分钟），也可在「自定义（分钟）」输入框填任意分钟数；选择「**无限**」则后端永不自动回收，只在主动停止时结束。

- 停止时宿主优先调用 HTTP `/stop` 端点**优雅退出**
- **内置 Debian 容器**：额外按进程组 `SIGKILL` 终止
- **实体 Termux**：空闲回收由共享 supervisor 统一管理（见 12.5.5），按各插件 `idle/<key>.start` 启动时间戳独立超时递归杀进程树，**不依赖插件实现 `/stop`**；宿主只做端口探测与状态清理。选「无限」时不写 idle 文件。请确保已授予 `com.termux.permission.RUN_COMMAND` 且开启「允许外部应用运行命令」

#### 12.5.4 实体 Termux 初始化命令

选择「实体 Termux」后，设置页会显示「**初始化命令**」卡片，点击复制图标即可复制到剪贴板，粘贴到 Termux 中执行一次即可：

```sh
mkdir -p ~/.termux; grep -q '^allow-external-apps=true' ~/.termux/termux.properties 2>/dev/null || echo 'allow-external-apps=true' >> ~/.termux/termux.properties; termux-setup-storage; termux-reload-settings 2>/dev/null || true
```

依次完成：
1. 写入 `allow-external-apps=true`（允许外部应用拉起 Termux）
2. `termux-setup-storage` 授权存储
3. `termux-reload-settings` 重载配置

> 若后端启动失败，宿主会自动检测缺失项并提示：`allow-external-apps` 未开启、未执行 `termux-setup-storage`、容器未安装或缺少 `RUN_COMMAND` 权限等，按提示操作即可。

#### 12.5.5 实体 Termux 共享 Supervisor

实体 Termux（proot 或本机模式）改用**单个常驻共享 supervisor**：容器/会话只初始化一次，所有插件后端作为 supervisor 的子进程运行，后续插件启动省掉 proot 初始化开销（冷启动约 5s）。内置 Debian 容器（约 2s）保持不变（每插件独立 proot）。

- 通信协议（控制目录 `<plugins根>/.uin/`）：`cmd/<key>.cmd`（启动命令）、`pid/<key>`（后端 PID）、`stop/<key>`（停止请求）、`idle/<key>`（空闲分钟数）、`idle/<key>.start`（启动时间戳）、`alive`（supervisor 存活标记）、`host_alive`（宿主心跳，每 30s touch，超时 300s supervisor 自退）、`shutdown`（退出标记）、`keep_alive`（后台保活标记）
- proot 启动：`proot-distro login <container> --bind '<plugins根>:/plugins' -- sh -lc 'sh /plugins/.uin/supervisor.sh /plugins'`
- 本机启动：`sh '<plugins根>/.uin/supervisor.sh' '<plugins根>'`
- 空闲回收：supervisor 按各插件 `idle/<key>.start` 启动时间戳独立超时递归杀进程树；`kill -0 $pid` 检测进程存活
- 宿主存活期间 supervisor 常驻；宿主退出时写 `shutdown` 标记，supervisor 自退
- 软件启动时后台自动预热 supervisor（`prewarm`），保存后端设置时同样触发
- 后端设置页新增「共享调度器」状态卡（RUN_COMMAND 权限 + supervisor 存活状态）
- **后台保活**（可选）：开启后 supervisor 不再因宿主进程被杀而退出，配合电池优化豁免 + 通知栏 + Shizuku/Dhizuku 权限保持后台存活

#### 12.5.6 运行环境如何生效

插件打开后，宿主按全局设置选择执行路径，并统一注入 `$PORT`、`$PLUGIN_ID`、`$PLUGIN_DIR`、`$WORK_DIR` 环境变量：

- **内置 Debian 容器**：`proot --link2symlink -0 -r <debian_rootfs> -b <插件目录>:/plugins/<id> -- sh -lc "<启动命令>"`
- **实体 Termux + 本机**：`bash -lc "<启动命令>"`（工作目录 = 插件目录）
- **实体 Termux + Proot 容器**：`proot-distro login <容器名> --bind <插件目录>:/plugins/<id> -- sh -lc "<启动命令>"`

插件无需感知运行环境，只要按约定读取环境变量、监听 `$PORT` 并实现 `/health` 与 `/stop` 即可。

#### 12.6 插件接收外部内容（openWith 中转，v5.4.0 新增）

从系统 / 其它应用「**分享**」或「**用其他应用打开**」的内容，可交给支持该内容的插件处理：

1. 在任意应用中点击「分享」或「用其他应用打开」，选择 **UIN Tool**
2. 进入「选择接收插件」中转页，展示已声明 `openWith` 且匹配该内容类型的插件
3. 点击某个插件，内容即交给它处理；只有 1 个匹配插件时自动打开

- 支持**文本 / 链接 / 文件（含一次多选）**三类内容
- 文件会自动复制进该插件的 `.incoming/` 目录，插件后端可直接读取
- 中转页支持 **搜索**：按插件显示名 / 插件 ID / 描述实时过滤
- 只有插件作者在 `plugin.json` 中声明 `openWith` 后，该插件才会出现在中转页与系统分享入口中

#### 12.7 插件多开（v5.4.0 新增）

同一插件可以同时运行**多个独立实例**：

- **Web / CUI 插件**：每次打开都是新实例，实例间页面状态、JS 接口、后端互不干扰
- **原生插件**：默认单实例（重复打开复用同一实例）；在「管理」→「开发工具」开启「原生插件多开（实验性）」后，每次打开新建独立实例
- 后端多实例（「开发工具」中的「每实例独立后端端口」开关）：**关闭**时多实例共享同一后端进程（共享端口）；**开启**时每个实例独享后端进程与端口，互不影响
- **保留会话单窗口（v5.5.0）**：「关闭时保留会话」开关默认**开启**（默认启用单窗口去重：共享端口模式 + Web 插件时同一插件只保留一个后台窗口，重复打开带到前台，不再多开实例）；用户可在「开发工具」中显式关闭后，Web / CUI 插件每次打开都是独立实例（支持多开）

   - **Web 插件**（有/无后端均可）：列出**尚未授予**的权限，提供「确定」「不再提示」「管理权限」——「管理权限」直接跳转到该插件的权限管理页
   - **原生插件**：列出所需（声明）权限，提供「确定」「不再显示」（每次打开都提示，除非选择不再显示）
3. 权限管理页仅管理 **Web 插件** 的权限（原生/CUI 插件不显示在权限管理页，原生权限由系统强制）；页面**没有刷新按钮**，授权 / 撤销后自动刷新列表；按钮行提供「**全部授权**」/「**全部撤销**」短文案按钮（v5.5.0 起改短，保证完整显示）
4. 权限授予后加载插件

### 13.4 权限持久化

> v5.5.0 起废弃旧版「按状态自动弹窗」的 `permission_state`（0/1/2 单值）API，权限状态改为按权限逐一判断（授予 / 封禁）。「不再提示/不再显示」选择按插件持久化（`plugin_permission_prompts`）。

### 13.5 Shizuku/Dhizuku 权限

v5.3.0 新增 Shizuku 与 Dhizuku 权限支持，**完全采用官方 API**（`dev.rikka.shizuku:api` / `dev.rikka.shizuku:provider` 与 `io.github.iamr0s:Dhizuku-API`）：
- **Shizuku**：`Shizuku.pingBinder()` + `checkSelfPermission()` 检测服务与授权状态；`Shizuku.requestPermission()` 请求授权，结果经 `addRequestPermissionResultListener` 回调**实时刷新**；Manifest 已注册 `rikka.shizuku.ShizukuProvider`
- **Dhizuku**：`Dhizuku.init()` + `isPermissionGranted()` 检测授权状态；`Dhizuku.requestPermission()` 请求授权，回调**实时刷新**

授予权限步骤：

1. 先在设备上安装 **Shizuku** 或 **Dhizuku** 应用（需用户自行安装对应 App）
2. 启动 Shizuku/Dhizuku 并完成其自身的启动/授权流程（如 Shizuku 通过 adb 或无线调试启动）
3. 进入 UIN Tool「管理」→「权限管理」页面，找到 **Shizuku / Dhizuku** 权限项
4. 应用会**检测服务与 API 权限授予状态**（服务是否可用 / 是否已授权）
5. 点击对应项，应用会**通过官方授权界面请求授权**，将本应用加入授权列表
6. 授权完成后返回应用，即可使用相关能力

## 十八、代码编辑器

自 6.2.0 起，代码编辑器不再只是插件创建向导里的草稿框，而是一个可独立调用的完整编辑器：文件树、多标签、直接读写磁盘、查找替换、语法高亮、代码格式化，其他应用也能通过「打开方式」把文件交给它打开。

### 18.1 打开方式

| 入口 | 说明 |
|---|---|
| 插件开发向导 | 向导中点击「打开代码编辑器」，编辑的是向导生成的草稿，保存后回写向导 |
| 其他应用「打开方式」 | 文件管理器、浏览器等把文件「用 UIN Tool 打开」，直接进入编辑器 |

支持的类型：`text/*`（txt、csv、markdown、日志等）以及 `application/json`、`application/xml`、`application/javascript`、`application/x-sh`、`application/x-yaml`；`file://` 与 `content://` 两种来源都支持。

> **注意**：系统「打开方式」选择器里会出现两个 UIN Tool 图标。这是有意保留的取舍——编辑器与插件中转页各自声明了 `ACTION_VIEW`，两者都可正常使用，选编辑器那个即进入编辑器。

进入时会申请存储权限：

| 系统版本 | 申请方式 |
|---|---|
| Android 11 及以上 | 需要「所有文件访问权限」，跳转系统设置页开启 |
| Android 10 及以下 | 申请读取 / 写入外部存储 |

未授权也可以浏览与查看（`content://` 来源本就不需要存储权限），只是无法写回磁盘，状态栏会显示「只读」。权限到手后目录树默认指向外部存储根目录，直接就能挑文件。

### 18.4 保存与文件访问

| 操作 | 说明 |
|---|---|
| 保存 | 顶栏保存图标（或 `Ctrl+S`），写回原文件；**按打开时判定的编码原样写回**，不会把 GBK 文件悄悄存成 UTF-8 |
| 另存为 | **长按**顶栏保存图标 → 弹出系统「另存为」，可同时另指定**文件名和位置**；当前标签随即切到新文件 |
| 退出确认 | 有未保存改动时按返回键，弹出「是否保存」，可保存 / 放弃 / 取消 |
| 返回键层级 | 设置页、查找面板、编码选择器、目录树抽屉打开时，系统返回键**由内向外逐层收起它们**，全部关完才轮到「未保存确认 → 退出」（6.1 在设置页按返回会直接退出编辑器） |
| 编码 | 状态栏的编码按钮 → 选择「自动检测」或手动指定编码。6.2.0 起可选列表扩充为**按本机能力过滤**的常用全集：UTF-8 / GB18030 / GBK / Big5 / UTF-16(LE/BE) / UTF-32(LE/BE) / Shift_JIS / EUC-JP / EUC-KR / ISO-8859-x / windows-125x / KOI8-R / TIS-620 等（设备不支持的编码不会出现在列表里，避免选了解不动）。**选手动会立即按该编码重新读取本文档**，状态栏随即显示所选值 |

**自动检测**：打开文件时按字节判定编码 —— 优先识别 BOM，其次做严格 UTF-8 校验，再判断是否为 GBK/GB18030（中文老文件），最后兜底 ISO-8859-1。6.1 及之前一律按 UTF-8 解码，GBK 文件读出来是 `锟斤拷` 之类乱码；6.2.0 起既会自动解对，也给了手动改正的入口。

**大小限制**：16MB 以上的文件一律自动以**分页窗口模式**打开（真分页、每页 2000 行，见 18.12）；其余文件只要剩余内存装得下就直接打开，且**读取前会先做内存预检**（预检按「3.25 倍峰值 + 强制回收」判定，且强制回收后**会等 GC 收尾完成再测量**，杜绝测量落在回收进行中造成的误拦；既有余量避免通过预检后读到一半 OOM，也不会刚关闭大文档内存未释放就被误判成「文件过大」），装不下直接给出「文件过大，内存不足」的明确提示，而不是先卡死十几秒（OOM 触发的反复 GC）再报错。反复用「打开方式」打开同一文件也**不再重新读取**（编辑器复用同一实例、直接切回已打开的标签），不会出现「第二次打开反而被判文件过大」。打开超大文件时建议保持「大文件省耗」开启（见 18.8），以免高亮与粘性滚动拖慢滚动。

**会话恢复**：进程被系统回收后从多任务窗口回来，会自动重新打开上次的文档，而不是落进「未打开文件」空态；插件向导模式则会恢复整套草稿。恢复失败（文件已删除、内存不足、分享方授权已回收）时，空态会**直接显示失败原因**，不再是笼统的「未打开文件」。

### 18.10 代码格式化

| 项目 | 说明 |
|---|---|
| 支持类型 | `json`、`json5`、`jsonc`、`yaml`、`yml`；**其余类型菜单项置灰**，不会出现「点了没反应」 |
| JSON 做法 | 逐 token 保值重排——只重算缩进与冒号后空格，数值、字符串、转义写法、键顺序、JSON5 单引号与尾逗号全部原样搬运 |
| YAML 做法 | 只做三件安全的事：块标量（`\|` / `>`）内逐字节保留、行首 Tab 展开为空格、清理行尾空白与连续空行。**不重排缩进层级** |
| 校验 | 内容不合法（括号不配对、字符串未闭合等）会提示「无法格式化」且**完全不动原文档** |
| 撤销 | 一次格式化合成为**一步撤销**，`Ctrl+Z` 一次即可整体还原 |
| XML 为何不支持 | 平台自带的 XML 序列化器是「美化排版器」而非保值重排：会统一属性引号、剥掉标签间空白文本节点、可能丢失 DOCTYPE 内部定义。这与「只动空白、绝不动值」的原则冲突；且本应用涉及的 XML 主要是 AndroidManifest 与布局文件，Android Studio 本身就会管格式 |

### 18.12 分页窗口模式（超大文件）

超过 16MB 的文件（以及内存预检失败、整文件装不下堆的文件）不再直接报「文件过大」，而是自动降级为**分页窗口模式**打开（EmEditor「磁盘溢写 + 区段窗口」的 Android 缩配）：

- **整文件不进内存**：打开时流式扫一遍建「每页首字节偏移 + 总行数」的小索引（10GB 级仅几十 KB），编辑器每次只载入**当前页**（2000 行）文本；
- 信息栏的字符数标注**「本页」**（该栏数字是当前页字符数而非全文），行号显示为**绝对行**（页码 × 2000 + 页内行）；编辑器行号栏里的数字是**页内相对行号**（每页从 1 重新计）；
- **分页控件是真翻页**：换页时当前页改动先落 spool（写回缓冲），再从磁盘读出新页；「跳转到行」输入的是**全文绝对行号**，会自动切到目标页再定位；
- **撤销/重做、格式化只作用于当前页**（撤销栈随换页重置）；查找/替换**一律按整档执行**（与是否分页无关）：逐页扫描、进度可查、可取消，结果按 `绝对行:列` 列表展示、点按跳页并高亮匹配；「全部替换（全文）」逐页改写进**磁盘写回缓冲**（内存恒定 = 一页），保存时与原文件流式拼接落盘，跨 2000 行页界的匹配会被识别并**跳过不替**（结果里上报数量），绝不产生跨页缝的半截改写；
- **替换进行中切到其他标签不会取消替换**：替换在后台继续跑完 —— 期间被替换的标签只读、保存/翻页/再发起替换会被挡，其他标签不受影响；完成后回到原标签可见「替换完成」结果横幅。关闭被替换的标签才会中止替换（原文件从未被替换触碰，不受影响）；
- **保存 = 原文件 + 改动页**流式拼接：未改动页按**原样字节拷贝**（不经过解码，原字节分毫不动），改动页按打开时的编码重编码；写临时文件后原子替换，并重建页索引。保存在后台线程进行，退出编辑器不中断（「保存并退出」不丢写）；
- 换编码会用新编码**重建索引**并回到第 1 页（与整读换档一致，重解覆盖当前编辑）；
- **另存为**暂不支持（整档不在内存，只能写出当前页）——直接保存到原文件即可；保存后若索引重建失败会临时锁只读并提示重新打开文件。

## 十九、常见问题

### 19.1 常见问题（Q1-Q28）

Q1: 如何获取更多插件？
A: 从「仓库」页面安装官方插件，或自己开发插件。

Q2: 插件安全吗？
A: 插件导入时进行 SHA-256 签名验证，插件权限独立控制。建议只从可信来源获取插件。

Q3: 工作目录在哪里？
A: 默认路径：/storage/emulated/0/UIN_Tool/

Q4: 终端功能如何使用？
A: 点击「开发」→「打开终端」，首次使用会自动安装 Linux 环境。

Q5: 原生插件编译失败？
A: 当前原生插件编译功能暂时禁用（Android 环境缺少 tools.jar 支持），建议使用 Web 插件或 PC 端编译。

Q6: Web 插件修改后不生效？
A: 关闭并重新打开插件即可，无需重新编译。

Q7: 插件权限如何管理？
A: 插件在 plugin.json 中声明权限，打开插件时会先弹权限提示框再打开：Web 插件提示尚未授予的权限（确定/不再提示/管理权限），原生插件提示所需权限（确定/不再显示）。权限管理页可管理 Web 插件的权限。

Q8: 应用闪退怎么办？
A: 重新打开应用（会自动显示崩溃日志），查看运行日志分析原因，或清除应用数据重装。

Q9: 如何自定义 UI 颜色？
A: 在「管理」→「UI 个性化」中调整颜色配置。

Q10: 如何更新 UIN Tool？
A: 启动自动检测新版本，或在「管理」→「检查更新」中手动检查。

Q11: 仓库页面加载失败？
A: 检查网络连接，下拉刷新重试，在「GitHub 加速」中配置镜像站。

Q12: 下载插件速度慢？
A: 在「GitHub 加速」中启用 CDN 加速，勾选更多的镜像站。

Q13: 小部件不显示插件？
A: 检查小部件是否已配置插件，尝试重新配置，刷新小部件列表。

Q14: 首次启动有引导页吗？
A: 首次安装或版本更新时会自动显示引导页。

Q15: 长按应用图标没有快捷方式？
A: 需要 Android 7.1+ 系统，部分第三方启动器可能不支持。

Q16: 什么是强制更新？
A: 当 Release Tag 格式为 {版本代码}-{版本名称}-1 时，会强制用户更新，无法跳过。

Q17: 如何导出开发模板？
A: 在「开发」页面点击「导出模板」，将内置的 7 个打包插件复制到 `/storage/emulated/0/UIN_Tool/templates/` 并生成 README.txt。

Q18: 图标着色开关有什么用？
A: 开启后所有图标使用主题色着色；关闭后图标保持原色。

Q19: 如何恢复 UI 配置？
A: 在「UI 个性化」中点击「重置」按钮。

Q20: 如何查看版本更新内容？
A: 点击「管理」→「文档中心」→「更新日志」

Q21: 如何创建带后端的 Web 插件？
A: 点击「创建插件」→ 选择「WebView + 后端」→ 填写后端启动命令（默认 `sh scripts/start.sh`）。向导自动生成 `scripts/start.sh` 与 `scripts/backend/server.py`，后端运行环境（内置 Debian 容器 / 实体 Termux）在「管理」页的「后端运行设置」中全局配置。

Q22: 后端需要安装什么？
A: 启动脚本 `scripts/start.sh` 会自动检测并安装依赖（`apt install python3` / `pkg install python`），无需手动安装第三方库。

Q23: 插件说明功能如何使用？
A: 在 plugin.json 中添加 notice 字段，首次打开时自动显示。

Q24: 代码编辑器支持哪些语言？
A: 支持 30+ 种编程语言，包括 Java、Kotlin、Python、JavaScript、TypeScript、HTML、CSS、JSON、XML、Markdown、Shell、SQL、Go、Rust、PHP、Ruby、Swift、Dart、Lua、Scala、Perl、Haskell、Elixir、Erlang、Clojure、Groovy、Dockerfile、Makefile、INI、Properties、TOML、YAML 等。

Q25: 插件数据存储在哪里？
A: 插件数据存储在 /storage/emulated/0/UIN_Tool/plugins/{pluginId}/data/ 目录，KV 数据存储在 SharedPreferences 中。更新插件时数据自动保留。

Q26: 如何清除插件数据？
A: Web 插件可使用 UINPlugin.clearStorage() 和 UINPlugin.clearCache()，或在「插件管理」中卸载插件。

Q27: 权限状态会持久化吗？
A: 会。权限授予/封禁状态按插件持久化；「不再提示/不再显示」选择也按插件持久化，选择后不再弹窗（原生插件每次打开都会提示，除非选择「不再显示」）。

Q28: 如何重置插件权限？
A: v5.5.0 起权限状态按权限逐一管理（授予 / 封禁），可在「插件管理 → 权限」页面为 Web 插件重置权限（授予 / 撤销 / 封禁）或解除「不再提示/不再显示」设置；原生插件权限由系统管理。旧版 `clearPermissionState()`（permission_state 单值）接口已废弃。

Q29: 如何创建 CUI 终端插件？
A: 「开发」→「创建插件」→ 选择「CUI 终端」，4 步向导会自动生成 `scripts/script.py` 示例脚本与启动命令配置，打开后在全屏终端中运行。

Q30: plugin.json 的权限怎么声明？
A: 使用**逗号分隔的字符串或 JSON 数组**均可（两种格式兼容解析），如 `"permissions": "android.permission.INTERNET,android.permission.VIBRATE"` 或 `"permissions": ["android.permission.INTERNET", "READ_CLIPBOARD"]`。伪权限（`READ_CLIPBOARD` / `WRITE_CLIPBOARD`）仅需声明即生效。

Q31: 为什么「WebView + 后端」插件导入后没有后端？
A: 旧版打包器对 Web 插件只打包 `web/`，不打包 `scripts/` 后端文件，需手动放入安装目录。v5.2.0 起打包已**递归整包项目目录**（`scripts/`、`scripts/backend/server.py`、`start.sh` 等全部打入 TPK），不再需要手动放置；同时向导生成的 `entry` 自 v5.1.0 起已正确指向 `web/index.html`。

Q32: 为什么打开插件时会弹权限提示框？
A: v5.5.0 起打开插件前会先弹权限提示：Web 插件列出尚未授予的权限（确定 / 不再提示 / 管理权限），原生插件列出所需权限（确定 / 不再显示）。选择「不再提示/不再显示」后可停止弹窗，权限管理页可重新管理 Web 插件权限。

Q33: 什么是新拟态风格？
A: 新拟态（Neumorphism）是一种 UI 设计风格，通过柔和的凹凸光影效果让界面元素看起来像是从背景中浮现或凹陷。在「管理」→「UI 个性化」→「特效」页开启，与玻璃效果互斥（同时只能开启一种）。

Q34: 如何切换应用语言？
A: 在「管理」→「UI 个性化」→「语言」页可直接切换应用显示语言（中文/英文等），无需更改系统语言，切换后即时生效。

Q35: 如何调节玻璃效果或新拟态的透明度？
A: 在「管理」→「UI 个性化」→「特效」页，开启玻璃效果或新拟态后会出现透明度滑块，拖动即可实时预览调整效果。
