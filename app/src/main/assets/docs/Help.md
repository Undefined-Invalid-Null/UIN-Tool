## 一、应用概述

UIN Tool 是一个轻量级的插件化框架应用，允许您动态加载和运行第三方插件。v5.4.0 版本是**主动能力扩展（capability）**：**新增插件接收外部内容**——系统/其它应用「分享」或「用其他应用打开」的文本、链接、文件可发送给 UIN Tool，中转页会列出所有声明 `openWith` 且匹配的插件供您选择交给哪个插件处理（仅 1 个匹配时自动打开，中转页支持实时搜索；文件会复制进插件 `.incoming/` 目录供后端读取，Web 插件可用 `window.getOpenData()` / `UINPlugin.getOpenData()` 读取，原生插件通过 `onHostEvent("host.open", bundle)` 接收）；**新增插件多开**——Web / CUI 插件默认支持多开（每次打开都是独立实例，页面/JS 接口/后端互不干扰），原生插件默认单实例、可在开发工具页开启「原生插件多开（实验性）」，每个实例拥有独立 `instanceId`，后端支持共享端口 / 独立端口两种多实例模式；同时**插件管理页列表项的启动按钮改为「新增桌面快捷方式」**（`＋` 图标）。v5.3.0 版本是一次**全面完善（refinement）**：**新增全局渐变背景**——在「UI 个性化」「效果」页可开启/关闭，支持单选（单色渐变）/多选（多色渐变）两种模式，可分别设置**起始/结束方向**（6 方向可选），默认单色渐变按主题自适应（浅色 `#FFC4D6DF` / 深色 `#FF4C4F51`，右下 → 左上），所有页面统一生效且**顶部标题栏跟随渐变**；**玻璃透明度调高**、**插件管理页卡片风格统一**（复选框仅在选择模式显示）、**底部导航悬浮样式**（完全遵照卡片风格：不透明卡片背景 + 圆角 + 阴影，覆盖在内容之上，滚动卡片从四周留白处露出不裁切，点击按压缩放、选中图标放大、无涟漪）与**按钮描边完善**（白色/透明背景的描边按钮轮廓清晰）；**弹窗背景跟随主背景**并保持较高透明度（0.95）保证文字可读，同时修复插件弹窗背景盖住插件页面内容的问题；**修复权限状态自动刷新**——授权后自动更新勾选，无需手动下拉刷新；**统一 UI 组件体系**——`Unified*` 组件成为唯一实现源（按钮/卡片/输入框/文本/开关/标签/对话框等），`UIComponents` 重构为薄委托层，全部屏幕迁移使用统一组件，卡片/输入框/对话框支持玻璃效果（半透明背景、无边框、无阴影、跟随主题）；**完善颜色选择器**——可视化取色器（色相条 + 饱和度/亮度面板，可点击/拖动任意位置拾取任意颜色），支持十六进制颜色输入，保留 RGB/Alpha 滑块与预设色板，支持夜间模式跟随主题；**增强插件分类管理**——插件详情页与导出/删除操作栏均可「更换分类」，支持批量修改与自定义新分类，插件详情弹窗新增「更换分类」「卸载」按钮（工具页长按插件也可操作）；**新增 Shizuku 与 Dhizuku 权限支持**（完全采用官方 API：`Shizuku.pingBinder()`/`checkSelfPermission()`/`requestPermission()` 与 `Dhizuku.init()`/`isPermissionGranted()`/`requestPermission()`，结果实时刷新）；同时**完善了代码结构**：镜像常量、文件工具、大小格式化均收敛到单一实现，Repository 命名统一（`IBackupRepository`）。v5.2.0 版本**完善了打包与更新逻辑**：打包递归整包项目目录（不再只打 `web/`）、每天一次的静默更新检查并统一更新弹窗 UI、内置 Termux 装 Alpine 提速（移除联网安装 proot-distro）；同时增强**开发向导**（打包不自动退出、配置字段补全 + 权限多选、JSON 语法高亮）与**代码编辑器**（文件树长按查看属性/重命名）、新增**插件管理页详情对话框**（plugin.json 字段 + 文件结构 + 插件大小）。v5.1.0 版本**重构了后端运行架构**：新增内置 Termux / 实体 Termux 全局运行环境切换与空闲自动回收，后端启动统一为「启动命令」模式，CUI 终端改前台直启并采用纯淡入转场；同时将**运行日志与开发者选项合并为「开发工具」页面**。v5.0.0 版本完成了**全量国际化（i18n）**、**动态 JSON 主题引擎**与**UI 全面优化**（下拉刷新统一、骨架屏、玻璃特效、界面动画等）。v4.5.0 版本新增了 **Proot 容器运行时**、**自定义后端（other）模式**和 **CUI 终端插件**，可通过共享 Alpine 容器隔离运行插件后端，也可以用全屏终端运行命令行插件。v4.4.4 版本统一了插件弹窗系统并修复了插件交互问题。v4.4.0 版本新增了**插件数据持久化存储**和**权限系统完善**。

### 1.1 核心功能

| 功能模块 | 说明 |
|----------|------|
| 插件系统 | 支持原生插件（Java/Kotlin）和 Web 插件（HTML/CSS/JS） |
| 数据持久化 | 每个插件独立的 data/ 目录，更新时自动保留用户数据 |
| 终端环境 | 内置基于 Termux 的完整 Linux 终端 |
| 后端集成 | Web 插件可启动后端服务（统一启动命令模式，内置 Termux / 实体 Termux 全局可选） |
| 容器运行时 | Proot 共享 Alpine 容器，后端与宿主机环境隔离 |
| 插件仓库 | 从 GitHub 官方仓库浏览、搜索和安装插件 |
| 开发工具 | 插件创建向导、代码编辑器（Sora Editor）、模板导出 |
| 权限管理 | 应用权限和插件独立权限管理，状态持久化 |
| 备份恢复 | 备份/恢复所有插件和配置 |
| UI 个性化 | 38+ 颜色项、7 种圆角、完整颜色选择器、全局渐变背景（方向可调） |
| 文档中心 | 开发文档、使用帮助、更新日志、关于信息 |
| 桌面小部件 | 列表小部件（3x3）和 1x1 快捷方式 |
| 外部内容接收 | 系统分享 / 用其他应用打开的中转处理（openWith），可接收文本 / 链接 / 文件 |
| 插件多开 | 同一插件同时运行多个独立实例（Web/CUI 默认，原生可选） |

### 1.2 插件类型对比

| 特性 | 原生插件 | Web 插件 |
|------|----------|----------|
| 开发语言 | Kotlin/Java | HTML/CSS/JS |
| 性能 | 最优 | 良好 |
| 热更新 | 需重新编译 | 无需编译 |
| 开发门槛 | 较高 | 较低 |
| 系统 API 访问 | 完全访问 | 通过 JS 接口（170+ API） |
| 数据存储 | PluginContext API | UINPlugin 存储 API |
| 后端支持 | 无 | 统一启动命令模式（内置 Termux / 实体 Termux 全局可选） |

## 二、首次启动

### 2.1 启动流程

用户点击图标 → 权限检查 → SplashActivity (启动页) → 检查首次启动

```
├── 是 → OnboardingActivity (引导页) → MainActivity
└── 否 → MainActivity
```

### 2.2 权限请求

首次启动时，应用会请求存储权限：

1. 显示权限说明对话框
2. 点击「去授权」跳转到系统设置
3. 授予权限后自动返回应用
4. 如果拒绝权限，应用会退出

### 2.3 引导页

首次安装或版本更新时，会自动显示引导页：

| 页面 | 内容 |
|------|------|
| 第1页 | 欢迎语 / 版本更新说明 |
| 第2页 | 插件管理功能介绍 |
| 第3页 | 插件开发工具介绍 |
| 第4页 | Web 插件支持介绍 |
| 第5页 | 准备就绪，开始体验 |

操作方式：
- 点击「下一步」翻页
- 点击「跳过」直接进入主界面
- 最后一页点击「开始体验」

## 五、终端功能（基于 Termux）

> 🔥 **v4.0.0 新增功能**：UIN Tool 内置完整的终端环境。

### 5.1 访问方式

1. 点击底部「开发」标签
2. 点击「打开终端」按钮
3. 首次使用会自动安装 Linux 环境

### 5.2 终端特性

| 特性 | 说明 |
|------|------|
| Shell 支持 | bash、zsh、fish 等主流 Shell |
| 包管理器 | APT (Debian/Ubuntu 软件源) |
| 开发工具 | gcc、clang、make、git 等 |
| 脚本语言 | Python、Node.js、Ruby、Perl 等 |
| 文本编辑器 | vim、nano、emacs 等 |
| 网络工具 | curl、wget、openssh 等 |
| 多会话 | 支持多个终端会话同时运行 |
| 多窗口 | Android 7.0+ 多窗口支持 |
| 自定义快捷键 | 可配置的硬件/软件键盘快捷键 |

### 5.3 常用命令

```bash
# 更新软件源
pkg update

# 安装 Python
pkg install python

# 安装 Node.js
pkg install nodejs

# 安装 git
pkg install git

# SSH 连接服务器
ssh user@hostname

# 查看存储目录
ls ~/storage/shared/
```

### 5.4 终端设置

1. 点击「终端设置」按钮
2. 可配置：

## 十、插件管理

### 10.1 插件格式说明

插件文件扩展名为 .tpk，本质上是 ZIP 压缩包。

原生插件结构：

```
plugin.tpk
├── plugin.json      # 插件配置文件
├── icon.png         # 插件图标 (建议 128x128)
├── plugin.dex       # 编译后的 DEX 文件
├── src/             # 源码目录
└── res/             # 资源文件目录
```

Web 插件结构：

```
plugin.tpk
├── plugin.json      # 插件配置文件
├── icon.png         # 插件图标
├── web/             # Web 资源目录
│   ├── index.html   # 入口页面 (必须)
│   ├── style.css    # 样式文件 (可选)
│   └── script.js    # JavaScript 文件 (可选)
├── data/            # ✅ 插件数据目录（运行时创建）
└── cache/           # ✅ 插件缓存目录（运行时创建）
```

### 10.2 plugin.json 配置说明

```json
{
    "pluginId": "com.example.myplugin",
    "version": 1,
    "versionName": "1.0.0",
    "minHostVersion": 1,
    "name": "我的插件",
    "author": "开发者",
    "description": "插件描述",
    "notice": "欢迎使用！首次打开会显示此说明",
    "icon": "icon.png",
    "apiLevel": 21,
    "uiType": "web",
    "entry": "web/index.html",
    "permissions": "android.permission.INTERNET,android.permission.VIBRATE",
    "backend": "other",
    "backendStartCommand": "sh scripts/start.sh",
    "backendStartEntry": "scripts/start.sh",
    "backendAutoStart": true,
    "backendTimeout": 30,
    "backendHealthCheck": "/health"
}
```

> 说明：`uiType: "native"` 的原生插件使用 `mainClass` 指定入口类，不需要 `entry` 与后端字段；上例为 Web + 后端插件（`uiType: "web"`、`entry` 指向 HTML 页面、后端走统一的 `backendStartCommand` 启动命令）。字段完整说明见开发文档 README 12.3。

### 11.5 插件数据持久化存储

v4.4.0 新增功能

每个插件拥有独立的数据存储空间，数据在插件更新时自动保留。

Web 插件存储 API：

```javascript
// KV 存储
UINPlugin.setStorage('username', 'JohnDoe');
const name = UINPlugin.getStorage('username');
UINPlugin.setStorageInt('score', 100);
UINPlugin.setStorageBool('isLoggedIn', true);
UINPlugin.setStorageJSON('config', JSON.stringify({theme: 'dark'}));

// 批量操作
UINPlugin.setStorageBatch(JSON.stringify({k1:'v1', k2:'v2'}));
const result = JSON.parse(UINPlugin.getStorageBatch('["k1","k2"]'));

// 文件操作
UINPlugin.writeFile('notes.txt', 'Hello World');
const content = UINPlugin.readFile('notes.txt');
UINPlugin.deleteFile('notes.txt');

// 数据统计
const stats = JSON.parse(UINPlugin.getStorageStats());
console.log('KV:', stats.kvCount, '文件:', stats.fileCount);

// 导入导出
const exported = UINPlugin.exportData();
UINPlugin.importData(exported);
```

原生插件存储 API：

```kotlin
val pctx = PluginContext(context, pluginDir)
pctx.putString("key", "value")
val value = pctx.getString("key")
pctx.writeFile("data.txt", "content")
val content = pctx.readFile("data.txt")
```

#### 12.5.1 后端实现：内置 Termux 还是实体 Termux

| 选项 | 说明 | 适合场景 |
|------|------|----------|
| **内置 Termux**（默认） | 使用应用内置的精简版 Termux，强制通过 Proot 共享 Alpine 容器运行后端，**无需安装任何东西** | 开箱即用，想省事 |
| **实体 Termux** | 调用设备上安装的 Termux（`com.termux`）运行后端，可用原生 Termux 生态 | 需要 pip/npm/apk 等完整软件包生态 |

- **内置 Termux**：Alpine rootfs 随应用内置（assets 离线恢复，约 19MB，首次一次性解压），不依赖网络安装
- **实体 Termux**：需设备已安装 Termux 并完成一次初始化，否则启动失败时会自动弹出引导

#### 12.5.2 后端环境（仅实体 Termux 可选）

| 选项 | 说明 |
|------|------|
| **Termux 本机** | 直接在 Termux 原生环境运行 |
| **Proot 容器** | 在 Proot 容器内运行（容器名可配置，默认 `alpine`，如 `ubuntu` 需先安装） |

- 选 Proot 容器需填写容器名，可用 `proot-distro list` 查看已安装容器
- 内置 Termux **强制**使用 Proot Alpine 容器，此项不适用

#### 12.5.3 空闲自动回收

后端空闲超过设定时长（3 / 5 / 10 / 15 分钟，默认 5 分钟）自动停止，避免长期占用资源；插件活动请求会刷新计时。

- 停止时宿主优先调用 HTTP `/stop` 端点**优雅退出**
- **实体 Termux 的进程宿主无法直接杀死**，优雅退出完全依赖 `/stop` 接口，因此插件后端脚本务必实现 `/stop`（向导生成的 `server.py` 已内置）

#### 12.5.4 实体 Termux 初始化命令

选择「实体 Termux」后，设置页会显示「**初始化命令**」卡片，点击复制图标即可复制到剪贴板，粘贴到 Termux 中执行一次即可：

```sh
mkdir -p ~/.termux; grep -q '^allow-external-apps=true' ~/.termux/termux.properties 2>/dev/null || echo 'allow-external-apps=true' >> ~/.termux/termux.properties; termux-setup-storage; termux-reload-settings 2>/dev/null || true
```

依次完成：
1. 写入 `allow-external-apps=true`（允许外部应用拉起 Termux）
2. `termux-setup-storage` 授权存储
3. `termux-reload-settings` 重载配置

> 若后端启动失败，宿主会自动检测缺失项并提示：`allow-external-apps` 未开启、未执行 `termux-setup-storage`、容器未安装或缺少 `RUN_COMMAND` 权限等，按提示操作即可。

#### 12.5.5 运行环境如何生效

插件打开后，宿主按全局设置选择执行路径，并统一注入 `$PORT`、`$PLUGIN_ID`、`$PLUGIN_DIR`、`$WORK_DIR` 环境变量：

- **内置 Termux**：`proot-distro login alpine --bind <插件目录>:/plugins/<id> -- sh -lc "<启动命令>"`
- **实体 Termux + 本机**：`bash -lc "<启动命令>"`（工作目录 = 插件目录）
- **实体 Termux + Proot 容器**：`proot-distro login <容器名> --bind <插件目录>:/plugins/<id> -- sh -lc "<启动命令>"`

插件无需感知运行环境，只要按约定读取环境变量、监听 `$PORT` 并实现 `/health` 与 `/stop` 即可。

#### 12.6 插件接收外部内容（openWith 中转，v5.4.0 新增）

从系统 / 其它应用「**分享**」或「**用其他应用打开**」的内容，可交给支持该内容的插件处理：

1. 在任意应用中点击「分享」或「用其他应用打开」，选择 **UIN Tool**
2. 进入「选择接收插件」中转页，展示已声明 `openWith` 且匹配该内容类型的插件
3. 点击某个插件，内容即交给它处理；只有 1 个匹配插件时自动打开

- 支持**文本 / 链接 / 文件（含一次多选）**三类内容
- 文件会自动复制进该插件的 `.incoming/` 目录，插件后端可直接读取
- 中转页支持 **搜索**：按插件显示名 / 插件 ID / 描述实时过滤
- 只有插件作者在 `plugin.json` 中声明 `openWith` 后，该插件才会出现在中转页与系统分享入口中

#### 12.7 插件多开（v5.4.0 新增）

同一插件可以同时运行**多个独立实例**：

- **Web / CUI 插件**：每次打开都是新实例，实例间页面状态、JS 接口、后端互不干扰
- **原生插件**：默认单实例（重复打开复用同一实例）；在「管理」→「开发工具」开启「原生插件多开（实验性）」后，每次打开新建独立实例
- 后端多实例（「开发工具」中的「每实例独立后端端口」开关）：**关闭**时多实例共享同一后端进程（共享端口）；**开启**时每个实例独享后端进程与端口，互不影响

### 13.3 插件权限管理

插件在 plugin.json 中声明所需权限：

```json
{
    "permissions": "android.permission.INTERNET,android.permission.VIBRATE"
}
```

> ⚠️ 权限以**逗号分隔的字符串**声明（宿主按 `,` 拆分）；写成 JSON 数组会被解析为空列表。

权限请求流程：

1. 插件安装时记录权限声明
2. 启动时自动检查权限状态
3. 缺失权限时显示说明对话框
4. 分组请求权限
5. 权限授予后加载插件

### 13.4 权限状态持久化

v4.4.0 新增功能

权限状态持久化存储，一次授权永久生效：

| 状态值 | 含义 | 行为 |
|---|---|---|
| 0 | 未授权 | 显示权限弹窗 |
| 1 | 已授权 | 直接进入插件 |
| 2 | 已拒绝 | 检查实际权限，缺失则弹窗 |

| 用户操作 | 状态变化 | 结果 |
|---|---|---|
| 点击"授权"，全部授予 | state = 1 | Toast "✅ 所有权限已授予" |
| 点击"授权"，部分拒绝 | state = 1 | Toast "⚠️ 权限被拒绝: XXX" |
| 点击"取消" | state = 2 | Toast "已取消权限请求"，退出 |

### 13.5 Shizuku/Dhizuku 权限

v5.3.0 新增 Shizuku 与 Dhizuku 权限支持，**完全采用官方 API**（`dev.rikka.shizuku:api` / `dev.rikka.shizuku:provider` 与 `io.github.iamr0s:Dhizuku-API`）：
- **Shizuku**：`Shizuku.pingBinder()` + `checkSelfPermission()` 检测服务与授权状态；`Shizuku.requestPermission()` 请求授权，结果经 `addRequestPermissionResultListener` 回调**实时刷新**；Manifest 已注册 `rikka.shizuku.ShizukuProvider`
- **Dhizuku**：`Dhizuku.init()` + `isPermissionGranted()` 检测授权状态；`Dhizuku.requestPermission()` 请求授权，回调**实时刷新**

授予权限步骤：

1. 先在设备上安装 **Shizuku** 或 **Dhizuku** 应用（需用户自行安装对应 App）
2. 启动 Shizuku/Dhizuku 并完成其自身的启动/授权流程（如 Shizuku 通过 adb 或无线调试启动）
3. 进入 UIN Tool「管理」→「权限管理」页面，找到 **Shizuku / Dhizuku** 权限项
4. 应用会**检测服务与 API 权限授予状态**（服务是否可用 / 是否已授权）
5. 点击对应项，应用会**通过官方授权界面请求授权**，将本应用加入授权列表
6. 授权完成后返回应用，即可使用相关能力

## 十八、常见问题

### 18.1 常见问题（Q1-Q28）

Q1: 如何获取更多插件？
A: 从「仓库」页面安装官方插件，或自己开发插件。

Q2: 插件安全吗？
A: 插件导入时进行 SHA-256 签名验证，插件权限独立控制。建议只从可信来源获取插件。

Q3: 工作目录在哪里？
A: 默认路径：/storage/emulated/0/UIN_Tool/

Q4: 终端功能如何使用？
A: 点击「开发」→「打开终端」，首次使用会自动安装 Linux 环境。

Q5: 原生插件编译失败？
A: 当前原生插件编译功能暂时禁用（Android 环境缺少 tools.jar 支持），建议使用 Web 插件或 PC 端编译。

Q6: Web 插件修改后不生效？
A: 关闭并重新打开插件即可，无需重新编译。

Q7: 插件权限如何管理？
A: 插件在 plugin.json 中声明权限，启动前自动检查并请求。

Q8: 应用闪退怎么办？
A: 重新打开应用（会自动显示崩溃日志），查看运行日志分析原因，或清除应用数据重装。

Q9: 如何自定义 UI 颜色？
A: 在「管理」→「UI 个性化」中调整颜色配置。

Q10: 如何更新 UIN Tool？
A: 启动自动检测新版本，或在「管理」→「检查更新」中手动检查。

Q11: 仓库页面加载失败？
A: 检查网络连接，下拉刷新重试，在「GitHub 加速」中配置镜像站。

Q12: 下载插件速度慢？
A: 在「GitHub 加速」中启用 CDN 加速，勾选更多的镜像站。

Q13: 小部件不显示插件？
A: 检查小部件是否已配置插件，尝试重新配置，刷新小部件列表。

Q14: 首次启动有引导页吗？
A: 首次安装或版本更新时会自动显示引导页。

Q15: 长按应用图标没有快捷方式？
A: 需要 Android 7.1+ 系统，部分第三方启动器可能不支持。

Q16: 什么是强制更新？
A: 当 Release Tag 格式为 {版本代码}-{版本名称}-1 时，会强制用户更新，无法跳过。

Q17: 如何导出开发模板？
A: 在「开发」页面点击「导出模板」，将内置的 7 个打包插件复制到 `/storage/emulated/0/UIN_Tool/templates/` 并生成 README.txt。

Q18: 图标着色开关有什么用？
A: 开启后所有图标使用主题色着色；关闭后图标保持原色。

Q19: 如何恢复 UI 配置？
A: 在「UI 个性化」中点击「重置」按钮。

Q20: 如何查看版本更新内容？
A: 点击「管理」→「文档中心」→「更新日志」

Q21: 如何创建带后端的 Web 插件？
A: 点击「创建插件」→ 选择「WebView + 后端」→ 填写后端启动命令（默认 `sh scripts/start.sh`）。向导自动生成 `scripts/start.sh` 与 `scripts/backend/server.py`，后端运行环境（内置 Termux / 实体 Termux）在「管理」页的「后端运行设置」中全局配置。

Q22: 后端需要安装什么？
A: 启动脚本 `scripts/start.sh` 会自动检测并安装依赖（`pkg install python` / `apk add python3`），无需手动安装第三方库。

Q23: 插件说明功能如何使用？
A: 在 plugin.json 中添加 notice 字段，首次打开时自动显示。

Q24: 代码编辑器支持哪些语言？
A: 支持 30+ 种编程语言，包括 Java、Kotlin、Python、JavaScript、TypeScript、HTML、CSS、JSON、XML、Markdown、Shell、SQL、Go、Rust、PHP、Ruby、Swift、Dart、Lua、Scala、Perl、Haskell、Elixir、Erlang、Clojure、Groovy、Dockerfile、Makefile、INI、Properties、TOML、YAML 等。

Q25: 插件数据存储在哪里？
A: 插件数据存储在 /storage/emulated/0/UIN_Tool/plugins/{pluginId}/data/ 目录，KV 数据存储在 SharedPreferences 中。更新插件时数据自动保留。

Q26: 如何清除插件数据？
A: Web 插件可使用 UINPlugin.clearStorage() 和 UINPlugin.clearCache()，或在「插件管理」中卸载插件。

Q27: 权限状态会持久化吗？
A: 会。一次授权后，权限状态永久保存，下次打开不再重复弹窗。

Q28: 如何重置插件权限状态？
A: 清除应用数据，或在开发者选项中重置权限状态。

Q29: 如何创建 CUI 终端插件？
A: 「开发」→「创建插件」→ 选择「CUI 终端」，4 步向导会自动生成 `scripts/script.py` 示例脚本与启动命令配置，打开后在全屏终端中运行。

Q30: plugin.json 的权限怎么声明？
A: 使用**逗号分隔的字符串**，如 `"permissions": "android.permission.INTERNET,android.permission.VIBRATE"`。写成 JSON 数组会被解析为空列表。

Q31: 为什么「WebView + 后端」插件导入后没有后端？
A: 旧版打包器对 Web 插件只打包 `web/`，不打包 `scripts/` 后端文件，需手动放入安装目录。v5.2.0 起打包已**递归整包项目目录**（`scripts/`、`scripts/backend/server.py`、`start.sh` 等全部打入 TPK），不再需要手动放置；同时向导生成的 `entry` 自 v5.1.0 起已正确指向 `web/index.html`。
